OPEN
The Orbit Brief is a source-grounded space-news question app. I built it to
apply what I learned from the Parsity medical RAG project to a smaller NASA
news corpus. Answers link back to the source records.

DEMO
Use these three questions:

1. How many articles are indexed from June?
   SQL only. Exact count and date boundary.

2. What has NASA said about Moon Base?
   RAG only. Semantic topic search over article chunks.

3. What did articles from June say about Moon Base?
   Both. This is the best demo question.

Mention source cards and terminal logs. The user sees a grounded answer and
validated sources, not the raw agent process.

HIGH-LEVEL OVERVIEW
Data:
NASA RSS for fresh items + official NASA archive for the 90-day backfill
-> Postgres Article store
-> clean article body extraction
-> sentence-aware chunks of about 1,500 characters, title included, no overlap
-> OpenAI embeddings
-> Pinecone dense-vector index

Corpus:
81 articles / 204 vectors / May 15 to August 11, 2026
Embedding model: text-embedding-3-small, 1,536 dimensions, cosine similarity.

Workflow:
question -> selector -> SQL and/or RAG -> aggregator -> JSON answer + sources

The selector chooses SQL, RAG, BOTH, or NEITHER through a Zod-validated plan.
SQL handles exact structured facts. RAG handles topic meaning. The aggregator
only sees selected evidence and the server validates source IDs before display.

INTERESTING LEARNING / REAL PROBLEM
The question “What did articles from June say about Moon Base?” exposed a real
limitation. Dense retrieval found relevant Moon Base chunks from May because it
matches semantic meaning, not hard date rules.

I did not add reranking. Reranking only reorders candidates. I needed to remove
ineligible evidence.

Fix:
SQL returns only June Article IDs. RAG retrieves Moon Base chunks. The app
filters out every RAG chunk whose articleId is not in the SQL June set before
the aggregator sees it. That makes the date constraint real, not prompt advice.

WHY THESE CHOICES?
Dense vectors:
Each chunk becomes 1,536 numbers representing its meaning. Similar meanings
sit close together, so “pollution from orbit” can retrieve TEMPO content.
Dense retrieval suits a small, single-source corpus where questions will mostly
be conceptual rather than exact-title searches.

Chunking:
Sentence boundaries avoid broken passages. About 1,500 characters retain useful
news context. No overlap avoids duplicate vectors and embedding cost. It is a
practical baseline, not a universal chunking rule.

SQL:
SQL is the canonical ingestion store: URLs, hashes, source records, dates, and
exact counts. Pinecone is the derived semantic index. SQL may be more than the
public question flow needs, but it made structured versus semantic retrieval
visible for the capstone and solved the June hard-constraint problem.

MODELS
text-embedding-3-small: cost-conscious semantic search baseline.
gpt-5-mini: selector and SQL planning, where structured decisions matter.
gpt-4o at temperature 0: grounded final synthesis from supplied evidence.

WHAT I DID NOT BUILD, AND WHY
Streaming: JSON keeps answer and validated sources together. Streaming needs a
structured event design for partial text, stages, sources, and errors.

Reranking: no evaluation evidence yet that the right result is retrieved but
ranked too low. The June bug was filtering, not ranking.

Web agent: the corpus boundary stays truthful. It needs an allowlist,
provenance, prompt-injection handling, and an ingestion decision.

Q&A QUICK ANSWERS

Why not only RAG plus metadata?
That is a credible future simplification. Most user questions will be semantic.
I would keep SQL for ingestion/admin and could route public questions mostly to
RAG with metadata filters if user behaviour supports it.

Why not use Pinecone metadata for June?
It is possible. The current deterministic post-retrieval filter was simpler and
tested for a 204-vector MVP. Numeric date filters need additional metadata and
a full re-upsert.

Why no SQL generated by the model?
The model creates a Zod-validated query plan. The application executes fixed
Prisma calls. It never executes model-authored SQL.

What does LangSmith add?
It shows the selector, SQL/RAG, and aggregator trace. The private demo project
also records the full OpenAI prompts and outputs, which helps debug latency and
evidence flow.

Remember:
You are showing learning and decisions, not claiming a finished product.
The working app plus one real evaluated failure and fix is enough.
